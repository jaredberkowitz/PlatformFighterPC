# Shared combat mechanics: inventory

What the engine can already do for a moveset, where it lives, who uses it, its knobs, its limits and the tests that protect it. Read this
before building anything for a new port: if a mechanic is here, reuse it; if it is close, extend it here (and update this file); only if
it is missing, build it, generally, and add a row.

Built from the code at sim version 55 (content schema 3), October 2026, and updated for sim 64 (content schema 4, the Embers' specials) and sim 66 (content schema 5: the Gauntlets' phase 1, with E17, E19, E24 and the `presses` registers) and sim 67 (the Staff's phase 1, with E26 angle types and E27 signed hitstun modifiers; no schema change), sims 67 to 72 (the Gauntlets' phase 2: the shield stun fix, E1 armor, the E11 additions, E21 search boxes, E6 command grabs, E3c no-clank hits, E22 off-edge versions, the `wall` register) and sim 73 (angle type 1 by travel, the Gauntlets' specials' angle types, the Staff's no-clank boxes, get-up attacks at angle 48), and sims 74 to 77 (the Staff's specials: E3a multi-hit piercing projectiles, E10c counter / reflector routing, the barrier's capsule and body fields, `air_max_rise`, counters catching through their own intangibility, the `flick`, `locked` / `lock_x` / `lock_y` registers and the `spawn_at` and `lock` functions, `collision::segment_blocked`; no schema change), and sim 83 (the Greatsword's phase 1: no new mechanic; the throws' several pre-hits and the jab's held repeat noted below), and sim 113 (the Pockets' phase 1: E39 random versions, E40 the previous version's hit rules, E41 balloons, `ChargedShot::power_to`, `Burst::on_hit`, `Item::angle`; no schema change), and sim 115 (the Pockets' phase 2: the jab cancel `Move::cancel_from`, E42 the pocket, E43 placed pieces, `combat::fire`, the `pocketed` register and `owns(kind)`; no schema change), and sim 117 (the Popgun's phase 1: E44 slip hits, E45 traps with an item's uses and damage modifier, E47 a move's toss with the `pull_wait` register, E48 a move that sheds a projectile when hit, the projectile registers `owner_stick_x` / `owner_stick_y`; no schema change), and sim 121 (the Dagger's phase 1: E52 partner boxes, E53 the gauge's partner rules, E54 damage over time and `Burst::on_shield`, E55 a guard's armor, the `powered` and `withstood` registers; no schema change), and sim 123 (the Dagger's phase 2: E56 the tether and blockable grab boxes, angle 365, dodges in a move, a part intangibility window's mode, the phantom's gauge from damage dealt; no schema change), and sim 125 (the Nodachi's phase 1: E57 the wing, Move::armor_mode, Move::edge_stop, E58 rings and twelve phases, empty follow-up slots; no schema change), and sim 119 (the Popgun's phase 2: E49 the latch,
E50 once-per-airtime marks and flag versions, E51 unblockable hits and self damage, `Hitbox::fixed_stun`, the `jump_tap` register; no
schema change), and sim 85 (content schema 6, the Greatsword's phase 2: E9 the gauge and its powered mode, E16 `boost` / `boosting` / `grab` / `boost_add`, E11 `start_speed_y` and `ledge_drop`, E22b `on_land`, E3f `Hitbox::half_height`). "Sword" is the Longsword (class 0, duelist body), "Claws" class 1
(brawler body), "Needles" class 2 (rogue body). File paths are from the repo root. Test names are the `#[test]` function names.

How a move flows (traced): `fighter::update` → `ground` / `airborne` → `start_ground_attack` / `start_air_attack` / `start_special` →
`begin_attack` (state `Attack`, `state_frame` 0, `hit_mask` 0, `charge` 0, script vars cleared on entering `Attack`) → each frame
`fighter::attack` (turn windows, smash charge, rehit, projectile request, script, motion or air physics or ground friction, end of move,
jab chain, ledge grab) → after every fighter has moved, `combat::resolve_hits` (collect, clank, apply), `grab::update`,
`combat::update_projectiles`, `combat::spawn_projectiles` (`sim-core/src/step.rs`).

## 7. Protecting tests outside sim-core

* `sim-content/tests/bundle.rs::the_hand_coded_roster_round_trips_exactly`: `content/base.pfc` equals the Rust builders.
* `sim-content/tests/recipes.rs::every_recipe_is_valid_content`, `creating_a_character_never_changes_the_other_fighters`.
* `sim-core/src/state.rs` checksum tests: each `GameState` field is in the hash (one case per field; add one for every new field).
* `sim-core/src/step.rs::random_play_keeps_invariants`, `restore_then_replay_matches_straight_run`; `pftool fuzz-rollback`, `pftool net-fuzz`.
  Since sim 87 both fuzzers draw their fighters from every class in the content, built-in or made from random stats, from the run's
  seed (`tools/src/main.rs::random_spec`; net-fuzz on its own generator, so a seed's network schedule does not depend on it), and print
  how many fighters of each class ran (`fighters per class [...]`); `fuzz-rollback` also takes `--only <seed>`. Before, both only ran
  classes 0 and 1 (net-fuzz's odd runs aside, which drew from the recipe classes).
* `netplay/tests/powered_rollback.rs`: four champions whose gauge fills on any damage, so random play keeps using the powered versions
  (bursts, the vortex, the finisher's hover); every rollback resimulates exactly.
